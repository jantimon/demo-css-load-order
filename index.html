01Why split CSS at all

The browser paints nothing until the CSS in <head> has loaded. A smaller file means an earlier first paint.

So we split CSS per page. Good idea, keep it.

02Simple Example with CSS Splitting

03Now let's click through the site

04Why this is so hard to fix

1Importing is not rendering

The CSS import runs once, when the module first loads. The function runs on every render. Nothing connects the two, so when <Home /> unmounts, there is no code that could remove home.css.

2Shared CSS lands in the cascade twice

Inside home.css, the bundler puts header.css before hero.css, as it should. But blog.css carries its own copy of header.css. With both chunks loaded, that copy can end up after hero.css, and the last rule wins.

3A priority system would need the whole import graph

Say CSS let a bundler give each file a priority, so a file always beats the files it imports. To compute that, the bundler needs the import graph of every page. One new import deep down changes the priority of every file above it.

Why @layer can't fix it

Layers are compared before specificity. Any unlayered rule beats every layered rule, even a more specific one. Move shared CSS into a layer, and its state rules start to lose.

base.css
@layer base {
  .btn { background: SlateBlue; }
  .btn:disabled {
    background: Gainsboro;
    color: DimGray;
  }
}
special.css · unlayered
.btn-hero { background: Crimson; }
